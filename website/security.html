Security & Governance

Autonomy that survives a compliance review.

Hiring is a regulated, high-stakes decision domain. Hire’s governance is not a policy document layered on top of the system — it is the system: human oversight, guardrails and provenance are structural properties of the orchestration.

Human Oversight

Who decides what — the complete matrix.

Agents never make a consequential decision about a person. They prepare; named human roles decide. Each gate is a typed contract the workflow physically cannot proceed without.

Defence in Depth

Four layers between a model and a mistake.

LAYER 1

Tool-enforced policy

Hard limits live inside tools: offers above the approved ceiling are rejected by code; calendar conflicts are rejected by the booking system. Prompt injection cannot override an if statement.

LAYER 2

Typed contracts

Every agent must terminate in a schema-validated structured output. Malformed or out-of-range results fail validation instead of flowing downstream.

LAYER 3

Orchestration policy

Loop caps (JD revisions, sourcing rounds, offer attempts), explicit routing, and least-privilege toolbelts — each agent can only touch its own stage’s systems.

LAYER 4

Trust-but-verify

After every agent run, the orchestrator validates mandatory artifacts against systems of record and backfills deterministically — logging every correction for reliability metrics.

Decision Provenance

Every hire can answer “why?” — forever.

For any candidate, the event log reconstructs the complete causal chain: which rubric scored them and how, who reviewed the flag, what the panel said, who made the hire call, what exception was approved and by whom. Adverse-action inquiries, internal audits and post-mortems read from the same record the system wrote in real time — not from memory.

Data handling

— Data minimisation in prompts: agents see only the fields their stage needs; BGV findings, for example, are excluded from screening context by construction.
— Credentials: LLM keys live in environment configuration or GCP Secret Manager — never in code, prompts or the repository.
— State residency: all workflow state sits in your database on your infrastructure; the only external calls are model inference.
— Provider choice: inference can run on Gemini, Claude, or their cloud-resident variants (Vertex AI / Bedrock) to meet data-processing requirements.

Deployment Models

Your infrastructure, your data, your keys.

GCP Compute Engine reference

Docker Compose on your VM: nginx serves this site and fronts the API; SQLite or Cloud SQL holds durable state; keys in Secret Manager or an instance-local .env. Ships in deploy/.

Cloud Run

The same containers, serverless: scale-to-zero between hiring waves, HTTPS and IAM out of the box, Cloud SQL Postgres for checkpoints.

Fully private

Air-gapped option: self-hosted models behind the same LangChain interface, no external inference calls at all. The orchestration doesn’t change.
