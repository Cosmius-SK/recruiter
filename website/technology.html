Technology

A governed graph of autonomous agents — engineered, not prompted.

TalentFlow is built on LangGraph (durable orchestration, interrupts, parallel fan-out, checkpointing) with frontier LLMs behind a provider-switchable factory. This page is the engineering tour: how routing, state, guardrails and testing actually work.

Design Stance

Two failure modes, deliberately avoided.

✕ The mega-agent

One agent, thirty tools, routing buried in a prompt. Impossible to govern, audit or test — behaviour drifts with every model update.

✕ The rigid pipeline

A fixed script with LLM calls sprinkled in. No autonomy, no adaptivity — RPA with extra steps and extra cost.

✓ The governed graph

Lifecycle policy is explicit, versionable code. Agents are genuinely autonomous inside their stage. Judgement junctures get adaptive LLM routing. Humans hold the gates.

Architecture

Three planes, cleanly separated.

PLANE 1 · ORCHESTRATION

The lifecycle graph

An 18-node LangGraph StateGraph. Nodes return Command(goto=…) so every transition is explicit and testable. Six interrupt() gates pause for humans; Send fans screening out in parallel; checkpointing makes all of it durable.

PLANE 2 · AGENTS

Eight specialists

Each runs an explicit tool-use loop — persona + toolbelt + iteration budget — and must terminate in a schema-validated structured output (Pydantic). The graph routes on typed artifacts, never on prose.

PLANE 3 · INTEGRATIONS

One adapter seam

HRIS, ATS, job boards, calendars, candidate comms, BGV vendor, ITSM — all behind one adapter layer. The shipped mocks are deterministic and seeded; swapping in Workday, Greenhouse or HireRight changes adapters, not agents.

Durable Execution

Interrupts are the universal wait primitive.

Every node boundary is checkpointed (SQLite in the demo, Postgres in production). A LangGraph interrupt() therefore serves both purposes with one mechanism:

Human approvals — the workflow parks with a typed payload; the decision arrives via Command(resume=…) from any surface.
External events — the interview wait parks the graph for days or weeks; an ATS webhook resumes it. The process can die, redeploy and restart in between — workflows continue exactly where they stopped.

Idempotency rule: a node containing interrupt() re-executes from its top on resume — so gate nodes contain only pure payload computation, the interrupt, and decision handling. LLM and tool work always lives in nodes that run exactly once.

# A human gate is ~10 lines. The payload is what an
# approval inbox renders; the answer resumes the graph.
def jd_approval_node(state) -> Command[...]:
    answer = interrupt(jd_approval_payload(state))
    if not answer["approved"]:
        return Command(goto="requisition",
            update={"jd_feedback": answer["feedback"]})
    if proposed > band.base_max:
        return Command(goto="finance_approval", ...)
    return Command(goto="sourcing", ...)

# Map-reduce: one screening branch per candidate.
def dispatch_screening(state):
    screened = {s.candidate_id for s in state["screening"]}
    todo = [c for c in state["candidates"]
            if c.id not in screened]
    return [Send("screen", {"candidate": c, ...})
            for c in todo]

Agent Runtime

Autonomy with a contract.

Each specialist runs an explicit tool loop (not a black-box prebuilt): the model decides which tools to call and in what order; the runtime executes them, feeds results back, enforces an iteration budget, and captures a full tool trace for the audit log.

Every agent then terminates in a structured output — ScreeningResult, OfferOutcome, RequisitionDraft — validated against a Pydantic schema. Downstream routing reads typed fields, never parses free text. That contract is what makes a probabilistic component safe to embed in a deterministic lifecycle.

Safety Model

Guardrails live in tools. Judgement lives in prompts.

The compensation ceiling is the canonical example. The Offer Agent is told the ceiling — but the extend_offer tool enforces it. A jailbroken, confused or hallucinating model cannot exceed comp policy, because the only path to the candidate runs through the tool. Raising the ceiling requires a human decision at the escalation gate — an audited, attributable state change, not a prompt edit.

Trust-but-verify completes the safety model: after each agent acts, the node validates mandatory artifacts against the systems of record (BGV case opened? tickets raised?) and backfills deterministically when something is missing — logged as a system event, so agent reliability is measurable from the audit trail.

@tool
def extend_offer(candidate_id, base, approved_max):
    """Extend an offer and return the candidate's reply."""
    if base > approved_max:
        return ("BLOCKED BY POLICY: exceeds the approved "
                "ceiling. Do NOT retry above it. Report "
                "status=needs_approval instead.")
    return store.candidate_offer_response(candidate_id, base)

Model Layer

Provider-switchable by one environment variable.

Every agent talks to the model through LangChain’s common interface (bind_tools + with_structured_output), so the provider is pure configuration — and per-agent tiering (a fast model for high-volume screening, a frontier model for negotiation) is a config change, not a refactor.

Control Plane

Four endpoints run the whole thing.

The REST surface is deliberately small because durable execution does the heavy lifting: starting, inspecting and resuming are the only verbs a workflow needs. This is the seam where Slack approvals, ATS webhooks and your HR portal plug in.

EndpointPurpose
POST /workflows Start a lifecycle from a hiring brief. Runs autonomously until the first human gate and returns the pending action.
GET /workflows/{id} Current stage, artifacts (shortlist, offer, onboarding plan) and the parked human action, if any.
POST /workflows/{id}/resume Deliver a human decision or external event — the body matches the gate’s typed expects contract.
GET /workflows/{id}/timeline The full audit trail: every agent action, human decision and system verification, attributed and timestamped.
Engineering Discipline

The orchestration is tested without an LLM.

The test suite drives the real graph end-to-end — real nodes, real interrupts, real checkpointing, real mock integrations — with a schema-aware scripted model standing in for the LLM. It asserts that exactly the right human gates fire, in lifecycle order, and the workflow lands on hired.

That separation is the point: the graph guarantees integrity; the LLM adds quality. Model upgrades can’t silently break the lifecycle, and CI needs no API keys.
